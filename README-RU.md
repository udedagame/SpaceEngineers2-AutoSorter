# AutoSorter 0.2.0 для Space Engineers 2

[English instructions](README.md) · [English description](DESCRIPTION-EN.md)

Первая экспериментальная версия. Плагин собран против установленной игры и прошёл проверку установки перехватчиков с её DLL. **Переносы в запущенном мире пока не проверены.**

## Что делает

Переименовывать контейнеры не нужно. Каждые 2 секунды назначение определяется заново по текущему содержимому:

| Содержимое | Назначение |
|---|---|
| Только руда (один или несколько видов) | Принимает руду |
| Только слитки/материалы (категория Material) | Принимает слитки/материалы |
| Только компоненты | Принимает компоненты |
| Пусто, смесь категорий или есть другие предметы | Общий контейнер, источник для сортировки |

Положите образец в каждый будущий склад. Смешанный груз в остальных контейнерах будет разбираться по этим складам. Пустые контейнеры не заполняются автоматически: сначала положите образец. Правильно размещённые предметы между одинаковыми складами не перекладываются.

Назначение НЕ сохраняется. Убрали последний предмет — оно сбросилось. Положили образец другой категории — назначение сменилось. Добавили другую категорию — контейнер стал общим. Если после разбора смеси осталась только одна категория, со следующего прохода контейнер принимает эту категорию. Чтобы сохранить смесь нетронутой, можно необязательно добавить `[NoSort]` или `[Не сортировать]` в название; это исключает контейнер полностью.

Старые метки `[Ore]`, `[Ingots]`, `[Components]` больше не задают назначение. Сортировщик ориентируется на содержимое. Смешанный контейнер служит источником, но не автоматическим получателем: иначе предметы могли бы ходить по кругу.

При заполнении цели остаток пробуется перенести в следующий подходящий склад; если свободной цели нет, он остаётся на месте. Проверяются направление конвейеров и фильтры для конкретного предмета. Инвентари персонажа и производства не участвуют. Инструменты и другие категории не перемещаются.

Область действия: загруженные ванильные грузовые контейнеры владельца текущего игрока, подключённые к конвейерам. Версия рассчитана на локальный мир с серверной симуляцией внутри процесса; удалённые и выделенные серверы не поддерживаются.

## Установка

1. Закройте игру и распакуйте **всю папку AutoSorter** из `AutoSorter-0.2.0.zip`, например в `D:\SE2Mods\AutoSorter`. Все DLL должны лежать рядом.
2. Steam → Space Engineers 2 → Свойства → Общие → Параметры запуска.
3. При использовании вместе с установленным BuildPlanner укажите ОДИН параметр:

```text
"-plugins:D:\SE2Mods\BuildPlanner\BuildPlanner.dll;D:\SE2Mods\AutoSorter\AutoSorter.dll"
```

Без BuildPlanner:

```text
"-plugins:D:\SE2Mods\AutoSorter\AutoSorter.dll"
```

Если уже есть `-plugins:`, добавьте путь через `;` внутрь существующего параметра. Не создавайте второй `-plugins:`: загрузчик игры читает только первый. Остальные параметры запуска сохраняйте.

4. Запустите игру. В `AutoSorter.log` рядом с DLL должны появиться `AutoSorter 0.2.0 ready` и `Input host captured`.
5. В мире положите образцы в контейнеры. Каждые 30 секунд лог сообщает число подходящих инвентарей и назначенных получателей. Успешные проходы записывают `moved=...` — число успешных операций, не число предметов.

## Первая проверка в игре

Используйте отдельный тестовый мир или копию своего мира, поскольку эта сборка ещё не прошла игровой тест.

1. Соедините три контейнера конвейерами. В первый положите только слиток, во второй только руду, в третий смесь руды и слитков. Ожидается разбор смеси по первым двум контейнерам. Проверьте суммарные количества.
2. Создайте склад компонентов, положив туда компонент. Компоненты из смешанного груза должны уйти туда.
3. Опустошите назначенный контейнер: автоматический приём должен прекратиться. Положите другой образец: он должен принимать новую категорию.
4. Добавьте к образцу предмет другой категории: контейнер становится общим. Проверьте случай с инструментом и рудой — инструмент остаётся.
5. Проверьте `[NoSort]`, заполненную цель и вторую свободную, разорванный конвейер и запрещающий/односторонний сортировщик.
6. Проверьте паузу, перезагрузку мира и совместный запуск с BuildPlanner.
В случае ошибки сохраните `AutoSorter.log`. Исключение при сортировке отключает её до перезагрузки мира; оригинальное обновление игры плагин продолжает вызывать.

## Настройки и отключение

`AutoSorter.json` рядом с DLL читается при запуске игры. После редактирования перезапустите игру.

- `Enabled`: включить/выключить сортировку.
- `IntervalSeconds`: 0.5–60 секунд; по умолчанию 2.
- `MaxTransferAttempts`: 1–1024 попыток переноса за проход; по умолчанию 64.
- `MaxItemChecks`: 1–4096 пар «источник/тип предмета» за проход; по умолчанию 256.
- `SoftTimeBudgetMs`: 1–100 мс; по умолчанию 10. Мягкий бюджет этапа маршрутизации, **не** жёсткий предел времени всего прохода: предварительное обнаружение контейнеров и отдельный вызов движка могут занять больше времени.
- `DryRun`: `true` включает поиск кандидатов без перемещения. `dryRunCandidates` — количество подходящих целей, не прогноз точного объёма переноса.

Плагин использует обход по кругу при ограничении объёма работы. Не сохраняет ссылки на контейнеры между проходами. Останавливается на паузе, при выгрузке и сохранении мира. Лог ограничен примерно 2 МБ плюс один предыдущий файл.

Для удаления уберите путь AutoSorter из `-plugins:`. Сохранения не требуют конвертации. Плагин не добавляет новые блоки и не меняет игровые файлы. Изменения расположения предметов, уже сохранённые игрой, остаются обычной частью мира.

## Сборка и проверка исходников

Нужен .NET SDK 9 и собственная установленная Space Engineers 2:

```powershell
dotnet build AutoSorter.csproj -c Release -p:GameDir="D:\SteamLibrary\steamapps\common\SpaceEngineers2\Game2"
dotnet run --project tests/AutoSorter.Tests.csproj -c Release
```

Проверки правил выполняются без запуска игры. Они не заменяют тесты игровых инвентарей, вместимости, сохранений и конвейеров. Обновления игры могут изменить внутренние API.

Исходный ориентир — BuildPlanner от Vito Pistelli, MIT: https://github.com/viligante8/SpaceEngineers2BuildPlanner . Его схему загрузки и примеры API использовали при разработке; исходники игрового движка и игровые DLL в пакет не входят. Уведомления о лицензиях приложены.
